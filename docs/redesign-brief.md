# DSH UI Usage Billing — 视觉与交互重构需求（Design Brief v2）

> 交给设计方（人或设计 AI）的完整重构需求。v2 补齐：美学方向锚点、可用令牌清单、画布尺寸、现状截图对照、真实数据样例、范围声明与流程。
> 配套文档：`docs/ui-ux-spec.md`（逐表面数据与交互细节）；现状截图 `screenshots/1-5.png`。

## 一、产品与用户

- **产品**：`@kenz1117/dsh-ui-usage-billing` —— DeepSeek Harness（DSH）宿主的费用与账单仪表盘插件。从会话日志聚合真实用量（调用 / Token / 缓存命中 / reasoning），按多厂商官方价格与订阅套餐（coding / token / agent 三类）折算人民币成本。
- **用户画像**：重度使用 AI 编码的个人开发者，同时接多家厂商（DeepSeek / Kimi / MiniMax / 智谱等），关心「今天烧了多少、哪个模型烧的、订阅额度还剩多少、峰谷切换前后价差」。
- **使用节奏**：
  - **瞥视级（0.5 秒）**：sidebar 计费卡、composer dock 即时代费条——扫一眼核心数字与告警
  - **研究级（1-5 分钟）**：dashboard 弹窗——趋势对比、异常下钻、单价核对、导出
  - **配置级（低频）**：设置页——单价表、预算、提醒、显隐偏好

## 三、美学方向锚点（需要设计方先定调）

现状是「克制冷调、中性为主、数据色点缀」。重构的视觉更新**希望更现代、更数据工具感**，给出三个候选方向，设计方选定或提出第四个：

- **方向 A · 数据终端感**（参照 Linear Insights / Vercel Analytics）：更紧凑的行距与等宽数字、细描边卡片、单色系 + 单一强调色、图表即主角。适合「专业监控工具」的定位。
- **方向 B · 柔和账单感**（参照 Raycast 设置 / 飞书统计页）：更大的卡片圆角与留白、低饱和色块分区、数字用衬线或高对比字重强调。适合「轻松记账」的定位。
- **方向 C · 混合**：壳层（计费卡 / dock / 提醒）走方向 A 的紧凑，仪表盘内部走方向 B 的分区呼吸感。

选定方向后，所有组件规格从该方向推导。

## 四、范围声明（重要）

- **功能冻结**：重构只动视觉与交互，**不新增/删除任何数据位、API、设置项**。数据面（宿主 `/api/*`）零改动。
- **结构例外**：设置页的信息架构可重组（卡片分组、网格布局），但每个设置项的 key、持久化机制（localStorage key、CustomEvent）、`data-testid` 必须保留。
- v1.0.18 已合并未发布的两个功能（Token 按模型视图、设置页聚合网格）**包含在重构范围内**，以它们为最新的结构基线。

## 七、逐表面重构需求

### Surface A — 计费卡（sidebar footer）

- 0.5 秒读完「今天/本月花了多少 + 一切正常吗」；主数字字重对比要拉开。
- 必须给出容器查询三档（200/170/110px）各自的布局方案。
- hover 态与「点击展开 dashboard」的 affordance。
- **触发弹层（triggerPop）**：hover/点击计费卡弹出的订阅额度详情——两种模式需分别设计：combined（全部订阅合并视图）/ subscription（仅显示选定套餐，含「未选目标」空态）。弹层内容：套餐名、额度进度（已用/总量 + 百分比）、到期时间、过期/耗尽态。

### Surface B — 仪表盘（六区 Tab）

- **概览**：Hero（本月费用）唯一锚点；同环比、月预计、KPI×4 降次级；热力图独立成块。给 2-3 个布局备选。
- **趋势**：7/30 天 + 结构/模型 + 费用/Token 的多维切换重新设计（v1.0.18 已加按模型视图与图例聚焦——聚焦时其余段 15% 透明、坐标轴不变，这个交互保留并纳入视觉稿）。
- **明细 / 统计**：明确两区职责切分（明细=流水，统计=聚合）；列对齐与等宽数字规则；长列表滚动与吸顶表头。
- **费率**：用户覆盖价加视觉标识；峰谷分时的时段呈现。
- **设置**：按用户意图重组信息架构（口径 / 提醒 / 显示 / 高级），组内保持紧凑行式与网格。

### Surface C — 即时代费条（dock）

- 单行 7 个信息块按价值排序降级：费用（必显）> 档位+倒计时 > 额度预警；给出窄 composer 的逐级隐藏方案。
- 显隐机制（localStorage + CustomEvent）保持，勿动。

### Surface D — 峰谷提醒 + 预算告警

- 统一告警骨架：图标 + 色阶 + 主文案 + 建议动作四段式；两种告警共享骨架、内容区分。

### Surface E — 系统通知（Notification API）

- 两个使用方共享同一通知模板：**对话完成通知**（会话 running→completed 时，默认关闭，设置页可开）与**峰谷切换 web 通知**（与页内 popover 同步弹出，可在峰谷设置里关闭）。
- 设计面：通知的标题/正文结构（会话名、费用摘要、切换预览等）、点击行为（聚焦宿主窗口并定位到相关界面）、权限首次请求的时机与话术（避免启动即索权）。
- 约束：系统通知的视觉由操作系统渲染，可控的只有标题/正文/图标——设计的重点是**文案模板**与**触发策略**，而非视觉样式。

## 八、真实数据样例（供 mockup 使用）

- **模型名**：`deepseek-chat` / `deepseek-reasoner` / `kimi-k2` / `minimax-m1` / `glm-4.7` 等（厂商：DeepSeek / 月之暗面 / MiniMax / 智谱）
- **订阅套餐**：coding（按月）、token（按量充值）、agent（按会话）；额度以「次 / Token 池」两种口径
- **峰谷时段**：峰时段（如 08:00-22:00）单价 ×2，谷时段 ×1；切换倒计时以分钟计
- **金额量级**：日费用 ¥0.5-¥30；本月 ¥20-¥400；单次会话 ¥0.01-¥2；Token 日量 1M-200M
- **缓存**：cache-hit 输入通常占输入总量 60-95%（命中率 KPI 的真实范围）

## 九、交付物

1. 全部表面（计费卡含触发弹层、仪表盘、dock 胶囊、设置页）的完整视觉稿，**暗/亮两态**（暗色为主要场景，优先核对）；系统通知补文案模板
2. 令牌映射表：视觉角色 → `--dsw-*` 令牌；不足处列「令牌申请」
3. 可复用组件规格：卡片、chips、表格、开关、Tab、Hero、空态——收敛到单一 CSS 定义
4. 交互标注：hover / focus / 展开 / 切换 / 加载骨架
5. 状态覆盖：空态（无会话日志）、错误态（API 失败）、加载态

## 十、实现流程与验收

- **流程**：设计稿 → 与插件作者评审一轮（修订）→ 交由插件作者实现（CSS Modules + 现有令牌）→ 312 个测试保持绿 → 发版。设计方无需写代码。
- **验收**：
  1. 四表面跨页一致性可辨认
  2. 概览 0.5 秒说出「本月花了多少、趋势是否异常」
  3. 设置页 ≤ 2 屏且每组职责可说清
  4. 暗/亮两态对比度全部可读
  5. 实现 bundle ≤ 256KB、312 测试绿、全部 `data-testid` 保留
